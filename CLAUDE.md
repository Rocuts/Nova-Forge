Bienvenido a Orbexs, el sitio web high-end de nuestra agencia de AI & Software.

- `/src/app`: Routing principal (SSR).
- `/src/components/sections`: Bloques modulares del hero/landing.

- Linter: `npm run lint`
- Build de prod: `npm run build`
- Tests E2E: `npm run test:e2e` (Playwright)

## Reglas de Arquitectura para Claude
- **NO DESTRUYAS EL SEO:** El archivo `src/app/[locale]/page.tsx` contiene un schema dinámico `@type: "FAQPage"` generado desde `dict.faq.items`. Si modificas la sección de FAQ (diccionarios `es.ts`/`en.ts`), el schema se sincroniza solo — no lo elimines. Lo mismo aplica a `src/app/[locale]/estudio-tiktok-live/page.tsx`, que genera su propio `FAQPage` desde `dict.liveStudio.faq.items`. Cada página define su `canonical`/`hreflang` con `buildAlternates()` de `src/lib/i18n.ts`.
- **Rutas nuevas:** una página se registra en tres lugares — la carpeta `src/app/[locale]/<slug-es>/`, `pathMap` en `src/lib/i18n.ts` y el array `pages` de `src/app/sitemap.ts`. Los rewrites del slug inglés y los redirects 308 se derivan automáticamente de `pathMap` en `next.config.ts` — no añadir entradas manuales ahí. Omitir pathMap o sitemap rompe el hreflang o el sitemap.
- **Proxy (ex-middleware):** el redirect de locale vive en `src/proxy.ts` (convención Next 16). No recrear `middleware.ts` en la raíz — Next 16 lo ignora silenciosamente y se rompe el redirect `/` → `/es`.
- **Orbexs Live Studio** (`/estudio-tiktok-live`) es la división de producción en vivo. Su lenguaje visual es dark-first con el par espectral cian/magenta (`--live-cyan` / `--live-magenta` en `globals.css`), usado solo como acento — nunca como relleno. La solicitud de agencia LIVE está **en revisión**: no escribas copy que afirme afiliación oficial con TikTok, y conserva el `disclaimer` del diccionario.
- **RealTy** (`/realty`) es el producto de infraestructura de ventas con IA para promotores inmobiliarios. Reglas:
  - **Nombre:** en la página solo existe *RealTy*. `RSDubai` es el nombre interno del repo del MVP (`~/Documents/GitHub/RSDubai`, referencia **read-only**: nunca se edita desde aquí) y no debe aparecer nunca en el sitio. Tampoco "Cierre Autónomo", "Realty.ia" ni "Redminds".
  - **Ruta:** mismo slug en ambos locales (`"/realty": { es: "/realty", en: "/realty" }`). Al ser idénticos, `next.config.ts` no deriva rewrite ni redirect 308 para ella — es correcto.
  - **Diccionarios:** todo el copy vive bajo la clave `realty` en `es.ts`/`en.ts`; el contrato de tipos es `RealtyContent` en `src/components/sections/realty/shared.tsx` (cambiarlo obliga a tocar ambos diccionarios). El `FAQPage` JSON-LD de `src/app/[locale]/realty/page.tsx` se genera desde `dict.realty.faq.items` — no lo elimines.
  - **Honestidad (regla dura):** cada capacidad se describe con su estado vía `statusLabels` (Construido / Validado · se activa en el piloto / Simulado / Adaptador de prueba / Planificado / No implementado; claves `built | validated | simulated | adapter | planned | notImplemented`). "Validado" es exclusivo del asesor de voz. Lo que no está construido se nombra como planificado en la misma frase.
  - **Demo de voz:** el flag `REALTY_VOICE_DEMO_ENABLED` se lee en build en `src/app/[locale]/realty/page.tsx` y baja como prop `voiceDemoEnabled` a `Voice` y `Status` — cambiarlo exige redeploy. El navegador pide sesión a `POST /api/realty/voice-session` (same-origin), y la ruta responde en uno de dos modos según el entorno: **public** (sin `ELEVENLABS_API_KEY`, agente público protegido por su allowlist de dominios en ElevenLabs — el cliente recibe el `agentId`) o **signed** (con clave, agente privado — el cliente recibe una URL firmada por sesión y la clave nunca sale del servidor). La demo tiene **cupo** (por navegador, por IP y presupuesto diario): el cupo se reserva al emitir la sesión y un 429 se muestra al visitante como mensaje de cupo, no como error. El SDK vive aislado en `VoiceDemoLive.tsx`, cargado con `next/dynamic({ ssr: false })` solo al pulsar el botón: no lo importes desde ningún otro sitio.
  - **Lenguaje (regla dura):** la landing habla a promotores y directores comerciales, no a revisores técnicos. Sin jerga de ingeniería en copy visible (HMAC, idempotencia, webhook, gateway, mock, fixture, JSON, API, LLM, nombres de librerías ni de funciones); los datos de demostración se etiquetan una sola vez por marco con `demoLabel`, no con badges por cifra. `e2e/realty.spec.ts` verifica la lista negra. Retenciones, reservas y depósitos: la palabra "simulado" aparece en la misma sección donde se nombran. Distingue siempre dos cosas sobre el agente de voz: (1) la **demo de voz en vivo en la web**, que existe solo cuando `REALTY_VOICE_DEMO_ENABLED=true` y se describe como conversación desde el navegador sobre un proyecto ficticio (`voice.live` + `status.liveVoiceRow`, chip `built`); (2) las **llamadas telefónicas del proyecto**, que se activan en el piloto — nunca escribir que el agente atiende llamadas del proyecto, ni que está operando o en llamadas, con la demo encendida o apagada. Con el flag apagado rige `voice.state` (chip `validated`, sin desplegar). Sin métricas, porcentajes, multiplicadores ni conteos de clientes: la única cifra de desempeño permitida es el objetivo de diseño "48–72 h" para activar un proyecto, **siempre** con su calificador (objetivo de diseño una vez cerradas las puertas del piloto; no es compromiso contractual ni propiedad del build actual). Prohibido mencionar Redminds o USD 15M.
- **Sin claims de partnership:** Orbexs NO tiene partnership ni certificación con AWS, Google Cloud, Azure, OpenAI ni TikTok — solo trabaja con sus productos. Todo copy (TrustBar incluido) debe leerse como "tecnologías con las que construimos", nunca como alianza, certificación o "confían en nosotros".
- **Tipografía:** Geist / Geist Mono (design system Orbexs). No reintroducir Inter ni otras fuentes.
- **Scroll y rendimiento 3D:** No hay librería de smooth scroll. `SmoothScroll` (`src/components/providers/SmoothScroll.tsx`) solo restaura el scroll al tope en cada navegación; el desplazamiento suave a anclas lo da `scroll-behavior: smooth` nativo (`src/app/globals.css`). No reintroducir `@studio-freight/lenis` ni equivalentes. Asegúrate que las transiciones de canvas 3D no bloqueen el hilo principal (main thread) usando `Suspense`.
- Si necesitas crear un nuevo componente, créalo bajo `/src/components/ui/` para componentes tontos, y `/src/components/sections/` para dominios complejos.
